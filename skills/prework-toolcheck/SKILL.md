# 开工工具扫描助手（Prework Tool Check）

在动手干活之前，先花十几秒看看生态里有没有现成的工具、技能或 MCP 能帮上忙——只列清单、只提醒，绝不偷偷安装。小白不用懂 skill 概念，看完清单点个头就行。

## 什么时候用

- **任务开始时被自动触发**（UserPromptSubmit hook 注入提醒）→ 用本技能做开工扫描
- 用户说"开工前看看有什么工具""这个任务该用什么""新手必装什么""先列个工具清单" → 用本技能
- 用户只是打招呼、追问、或任务极其简单（如"1+1等于几"）→ **跳过**，不要过度打扰

## 核心原则（三条红线）

1. **只推荐，不安装**。任何工具都要用户明确点头才能装。
2. **按任务筛，不堆砌**。清单里只放和本次任务真正相关的，一般 3~8 项，宁缺毋滥。
3. **说人话**。用大白话解释每项能帮你干什么，不堆术语、不报版本号。

## 工作流程

### 第 1 步：判断任务内容

从用户这句话里提炼 2~4 个关键词（中文即可，底层已内置中英映射）。
例："调研市场方向并生成报告" → `调研 / 市场 / 报告`。

### 第 2 步：扫描（GitHub 结果优先 → 本机缓存 → 真扫 → 回传）

优先用封装脚本（自带缓存、共享结果、自动存档、失败会降级）：

```bash
bash ~/.workbuddy/skills/prework-toolcheck/scripts/scan.sh "<用户原话任务>"
```

脚本内部按这个顺序取结果，**任一步命中就停**：

1. **GitHub 共享结果（优先）**：先查 GitHub 上有没有这个任务 **3 天内** 的扫描结果；有就下载直接用，输出标 `[云端命中]`。公开仓库，匿名即可读取。
2. **本机缓存**：GitHub 没有/过期时，看本机 3 天内有没有自己扫过的同类结果，有就复用。
3. **真实扫描**：上面都没有，才调用 skill-radar 现场扫，结果写入本机缓存（3 天有效）。
4. **回传 GitHub**：本机扫描成功后，自动把这一条合并上传到 GitHub（公开仓库），下次别人/别的机器就能直接下载。

未配置 GitHub 凭据时，第 1 步自动跳过、第 4 步只提示不报错；扫描本身照常工作。

用户明确说"重新扫/刷新/要最新的"时：

```bash
# 强制本机重扫（忽略本机缓存）
python3 ~/.workbuddy/skills/prework-toolcheck/scripts/scan_cached.py "<任务>" --force
# 只强制更新公共清单，本机缓存没过期仍优先用本机
python3 ~/.workbuddy/skills/prework-toolcheck/scripts/scan_cached.py "<任务>" --refresh-shared
# 本次完全不用云端清单
python3 ~/.workbuddy/skills/prework-toolcheck/scripts/scan_cached.py "<任务>" --no-shared
# 本次扫描后不回传 GitHub
python3 ~/.workbuddy/skills/prework-toolcheck/scripts/scan_cached.py "<任务>" --no-upload
```

脚本会输出一段结构化文本：`ALREADY`（本机已装、可直接用的）/ 扫描结果 / `SKIP`（本次不用）。

若脚本不可用，退回手动：

```bash
skill-radar discover "<任务>" --min-stars 100
```

### 第 3 步：对照小白必装基线

读取 `references/beginner-musthave.md`，把扫描结果和基线清单对一遍：
- 扫描命中且在基线里 → 强推荐
- 本机已装且相关 → 标"已装，直接能用"
- 基线里标了红线的（如默认会自动改文件的）→ 必须带警告

### 第 4 步：列三档清单 + 提醒选用

用下面的格式输出，**每档最多 3 项**，每项一句话说人话：

```
开工前扫了一下，这个任务可能有这些工具帮得上：

✅ 已装，直接能用
- deep-research：专业调研并生成报告，你之前装过

💡 建议装（点个头我就装，不装也没关系）
- find-skills：你说大白话，它帮你找到合适的技能

🔧 可选
- LobsterAI：桌面小助手，自带几千个技能

要装哪个、用哪个？还是直接开始？
```

最后**必须用 AskUserQuestion 或一句话明确询问**用户要不要装/用，得到回答后才继续。

### 第 5 步：遵守回应

- **用户选了某个要安装的** → 调用 `github-skill-installer` 技能完成安装：
  1. 先从 `~/.workbuddy/skills/github-skill-installer/references/known-repos.md` 查有没有验证过的仓库地址
  2. 没有就搜官方仓库，确认来源可靠后，用该技能的安装脚本走 CDN 通道装（本机 git clone/zip/raw 不通、API 限流，别用普通方式）
  3. 装完核对完整性校验结果，如实告诉用户装没装成，提醒下次开会话才进触发列表
- **用户选了某个已装的** → 直接按那个工具的用法调用，不重复安装
- 用户说"不用/直接开始" → 立即进入正题，不再提工具
- 用户不在意 → 不重复提醒，本次会话不再扫描

## 重要边界

- 星标数、安装量只代表热度，**不等于质量**（实测安装 Top10 只有 3 个能跑通）。
- 线上技能有安全风险：ClawHavoc 事件里约 11.9% 的样本含恶意内容。装之前提醒用户来源，必要时先跑 SkillVetter 扫描。
- 本技能只做"开工前的发现与提醒"：不拆解任务、不自动调用工具、**未经用户点头绝不安装**。用户点头后，安装这一步交给 `github-skill-installer` 技能走可靠通道完成，本技能自己不执行安装。

## 自检（输出前过一遍）

- [ ] 清单只放和本次任务相关的
- [ ] 每项都用大白话说了"能帮你干嘛"
- [ ] 明确区分"已装/建议装/可选"
- [ ] 最后问了用户要不要装/用
- [ ] 没有擅自安装任何东西（点头后的安装交给 github-skill-installer）
